# Web / 语音统一运行

> 后续状态（2026-10-25）：run/web 已统一为同一入口，语音均默认关闭、由界面按钮开启；下面“web 保持无音频”是原阶段目标，已由后续语音开关实现替代。当前行为见 [项目架构](../../architecture.md)。

依据：通用 Agent 规格与 Web MVP 的下一步；用户已验收对话并要求继续。

目标：`run` 在一个进程中提供 Web 与灵矽入口；`web` 保持无音频。builtin MCP 任务通过同步适配器投递到 Web 所在事件循环，复用 Runtime、SQLite 和取消清理。配置更新供下一任务读取。显式选择 CLI 后端的配置继续有效。

- [x] WebState 支持语音任务工作目录、共享运行查询和停止；tools 绑定服务适配器，退出时撤销绑定。
- [x] FastAPI lifespan 管理可选 Device，语音失败不关闭 Web；run 替换旧面板，收口 WebSocket 子任务取消。
- [x] 工作台展示语音状态与最近对话，自动发现选中会话中的语音运行；设置和状态使用同一份配置。
- [x] 命令行验证 MCP/Web 双向互斥、跨入口停止、配置即时生效、语音启动失败隔离和退出清理；更新文档、检查、提交推送。

限制：不新增协议、不实现自定义模型 `/v1`、不改动实际用户配置、不自动采音、不操作浏览器；跨进程互斥仍不支持。真实语音验收待用户在设备前完成。

## 验证

`./scripts/check.sh`、`npm run build` 通过。隔离目录与本地模型 HTTP 服务实测：MCP/Web 双向互斥、从 Web 停语音任务、从 MCP 停 Web 任务、修改工作区后语音工具在新目录写文件、SSE 回放和重启持久化。模拟 Device 启动失败仍可访问 Web，验证没有打开麦克风。独立审查发现空闲轮询会强制滚到底部，已改为按会话/消息数量/实时事件变化滚动。
