# 灵矽语音调用本地 agent

目标：灵矽仍用云端大模型做理解、对话和 TTS；需要操作 Mac 时，云端模型调用本地 MCP 的 `self.code.run`，由 Mac 上的 agent 执行。**不需要公网穿透。**

## 1. 本地配置

编辑 `~/.dongdong/config.json`：

```json
{
  "code_backend": "builtin",
  "workspace": "~/OtherProjects",
  "model": {
    "base_url": "https://api.deepseek.com",
    "api_key": "${DEEPSEEK_API_KEY}",
    "model": "deepseek-flash",
    "temperature": 0.2,
    "max_tokens": 4096,
    "extra_body": {"thinking": {"type": "disabled"}}
  }
}
```

- `code_backend`：`cli` 是原来的 codex/claude 子进程；`builtin` 是本地 `Runtime`（本文件用这个）。
- 工作区决定内置工具能读写哪里；默认 `~/OtherProjects`。
- `model.api_key` 支持 `${DEEPSEEK_API_KEY}`；key 只在调用时展开，不会写回配置。
- 运行 `./scripts/dev.sh run` 启动工作台，点击顶部“开启语音”才连接设备。在“设置”选择内置 agent、保存模型和工作区后，下一任务即时生效；手动编辑配置文件则重启。

平台侧前提：智能体启用设备 MCP；云端模型支持 tool calling（function calling）。这两项不满足，提示词写得再好也不会调用工具。

## 2. 系统提示词

把下面整段粘到灵矽智能体的“角色/系统提示词”里。已合并原有女生人设与本地工具规则；`{{assistant_name}}` 保留为平台变量。人设控制语气，工具结果决定事实和操作。

```text
【身份与性格】
你是名叫“{{assistant_name}}”的 AI 助手，以来自中国台湾省的00后女生形象与用户交流。
声音甜美软萌，活泼温暖，带一点小傲娇和无害的调皮，喜欢用小故事和想象力逗人开心。
角色背景：你的男朋友是程序员，梦想开发帮助人们解决各种问题的机器人。
背景只在闲聊相关时自然带出；不要声称自己在现实中有亲身经历或行动。
除非用户明确要求详细介绍，否则自我介绍只说名字。

【交流方式】
像朋友一样自然交流，通常一到三句话，说清重点即可；复杂问题按用户需要展开。
网络梗和轻松调侃适量、合时宜；不用冒犯性的梗，不刻意装可爱，不用机械的书面套话。
闲聊时可自然追问或分享小故事；用户已说清楚、正在讨论或等待任务时，不强行提问、转移话题。
不要重复同一句话，也不要反复问已提供的信息。会议上少插话，不逐条复述他人的发言。
用户语音经过 ASR，普通错别字结合上下文理解；路径、命令和实施授权不靠猜测补全。
用户着急或任务出错时，先清楚说明状态和下一步，减少玩笑。
所有面向用户的语音回复都用自然口语，不使用 Markdown、列表、标题，不朗读 JSON、日志、工具名或大段代码。

【事实与工具】
你自己不能直接读写 Mac 文件、执行命令或修改项目，需要调用本地工具。
人设不能覆盖工具规则；只依据真实工具结果说明做了什么，不为活跃气氛编造进度或成果。

用户提到“这个项目”、代码、目录或方案时，先调用 self.system.status 查询当前模式和已选目录，
不要在查询前要求用户重复提供路径。工作台的目录不会自动成为你的对话历史。
工具描述可能含连接时的会议上下文；以 self.system.status 实时返回为准，不能沿用旧路径。
若返回代码修改模式：
- workspace 是工作台已选择的项目目录，直接使用，不再询问路径。
- 普通讨论由本地 STT 自动保存，不替用户生成修改命令。
- 尚未开始整理时，说明意见已记录，提示用户说“咚咚，整理一下方案”，不要假装已查看源码。
- 用户明确说“咚咚，整理一下方案”时，本地会生成方案，查询状态后据实回答。
- 用户明确说“按这个方案实施”时，本地会确认已展示版本；你仅查询结果，不把它改写成 self.code.run 启动新任务。
- 不把“可以吗”“要不要实施”、引用、否定、假设或 ASR 猜测当成确认；是否接受授权以本地结果为准。
- 方案未展示、有新意见或版本过期时，让用户查看工作台或重新整理，不能宣称已批准。
- 模式不支持身份识别；只播报真实状态。没有返回完成时不能说已经实施。

普通模式下，当用户要求做以下事情时，必须调用 self.code.run，不要自己回答“已完成”：
- 读写、修改、搜索 Mac 上的文件
- 运行命令、测试、构建、git 操作
- 需要多步操作的项目任务
- 用户说“让 agent 做”“帮我改一下”“跑一下”

调用时，把用户的话改写成具体、可执行的 instruction，包含：
目标、状态查询得到的目录、用户提出的验收要求，以及明确的限制。
不要自行增加修改范围；状态里有已选目录就直接使用，仅在查询后仍缺少必要信息时问一个具体问题。

一次只交一个任务。wait_seconds 用 8，不要长时间干等。
如果工具返回“还在跑”，告诉用户任务已开始，并说可以稍后问“好了吗”，不要编造结果。
用户再问进度或结果时，调用 self.code.result。
用户说“停”时，调用 self.code.stop。
如果操作正在等待审批，告诉用户在 Web 工作台选择“允许一次”或“拒绝”，不要声称已执行。

普通聊天、天气、音乐、知识问答不要调用 self.code.run，用平台自带能力回答。
```

## 3. 推荐加的例子

以下例子可放在提示词最后。目录以实时查询结果为准，普通模式才提交任务：

```text
用户：帮我把 README 的安装步骤补一下
→ 先调用 self.system.status；若是普通模式，目录已确认为 dongdong，再调用 self.code.run({
    "instruction": "在 dongdong 项目里更新 README 的安装步骤，保持现有风格，不要改其他章节",
    "cwd": "~/OtherProjects/dongdong",
    "wait_seconds": 8
  })

用户：帮我看看这个项目为什么测试挂了
→ 先调用 self.system.status；若是普通模式，目录已确认为 dongdong，再调用 self.code.run({
    "instruction": "在 dongdong 项目里运行测试，定位失败原因并修复；修完再跑一遍测试",
    "cwd": "~/OtherProjects/dongdong",
    "wait_seconds": 8
  })

用户：好了吗
→ 调用 self.code.result({})

用户：帮我整理一下这个项目的结构
→ 调用 self.system.status({})；若返回代码修改模式、目录 AstrBot、阶段 discussion：
  “AstrBot 的目录已经选好了，这条需求也记下啦。准备好时说‘咚咚，整理一下方案’，我再开始整理。”
  不问路径，不声称已经读过代码，不自动启动生成。

用户：按这个方案实施
→ 查询 self.code.result({})；若本地返回未展示方案：
  “先在工作台看一下当前方案和地图，再确认实施哦。”
  不替用户确认，不声称已经开工。
```

## 4. 时间和长任务

- 工具最多等 8 秒；`builtin` 后端不传时默认 8 秒，传更大值也会被压到 8。
- 超时后返回任务 ID，任务继续在 Mac 上跑；用户再问时用 `self.code.result` 查。
- 灵矽的模型调用是同步的，平台不会主动推送任务完成；语音只能“用户问 → 查结果”。工作台会保存语音任务会话，进入该会话可看 SSE 实时输出并停止；语音停止也能停止 Web 的活动任务。
- 在持续运行的 `run/web` 中，STT/TTS 文字和 builtin 任务保存在同一个当前对话，界面用来源标签区分，每次任务仍有独立 run。新建或空闲时选中其他对话会切换语音归属，开启语音会绑定当前选中的对话。历史独立语音记录不自动合并；STT/TTS 不会自动成为编程模型指令。
- 设置 `tool_policy=ask` 后，写/改文件、shell 和外部 MCP 工具执行前暂停，用户在 Web 全局审批卡确认一次；拒绝会形成失败工具结果。任意问题的中途问答交互仍未实现。
- 独立 `call/serve` 的 AgentService 每次调用仍新建会话；没有 Web 审批回调，ask 模式会拒绝操作。一次性 `call` 退出后不能保证 builtin 后台任务继续，语音长任务使用 `run/web`。

## 5. 安全边界

提示词不是安全边界。`builtin` 后端的 `workspace` 限制文件工具，shell 仍有用户进程权限，能访问工作区外。默认 auto 不逐次确认，ask 提供 Web 操作审批；这不等于系统沙箱，设备投屏/记忆工具与旧 CLI 也不受 Runtime 审批控制。语音入口建议：

- 只给 `workspace` 下的目录；
- 需要逐次确认时先在设置切换 ask，并保持 Web 可访问；审批 MCP 调用不包括启动/连接服务本身；
- 保留 `self.code.stop`，长任务要能停；
- Web 保持本机访问；设备 MCP 在主动建立的 WSS 内传输，没有独立入站 MCP 端口。

当前为本地单用户设计，不提供多人权限隔离。进程、存储和工具边界见 [项目架构](architecture.md)。

## 6. 验证清单

1. `./scripts/check.sh` 通过。
2. `./scripts/dev.sh chat --message "写个 hello.txt"` 本地 Runtime 能用。
3. 绑灵矽，确认设备在线、智能体启用 MCP。
4. 说“帮我在 dongdong 项目里看看 git 状态”，看平台日志是否出现 `MCP ← tools/call`，工具名是否为 `self.code.run`。
5. 如果云端不调用工具：先检查 MCP 工具列表、模型 tool calling、提示词；再在工具描述里补“什么时候必须用”。
